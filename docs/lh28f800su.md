# LH28F800SU: x16 flash command set, status and pins

Status: transcribed from the published Sharp datasheet, *LH28F800SU 8M Flash Memory*, SMT96107
(May 1996), printed pages 1 to 14. Page numbers are printed pages, which match the PDF pages. This import did not
re-check the PDF. No source examined here ties this part to any SGI board, so the board that carries it and its
pin wiring are unknown. The constants, command opcodes and status fields are in `defs/lh28f800su.toml`, and the
generated reference is `gen/docs/lh28f800su.md`. The 512 KiB part that O2 boards carry is on the
[AT29C040A page](at29c040a.md), and the AMD AM29LV800B named in the base board note is in [baseio.md](baseio.md).

Labels: **established** means the datasheet states it. **Inferred** means a reading of the datasheet's tables or
arithmetic on a stated value. **Unknown** means the datasheet does not settle it.

## Array and blocks (established, pp. 2, 4 to 7)

- The array is 1 MiB, in sixteen independently lockable 64 KiB blocks of 32,768 words each.
- In x16 mode `BYTE` is high, `A0` is unused, and `A1` is the lowest word address input.

## Pins

- Both `CE0` and `CE1` must be low to select the chip. `OE` low enables output. A rising edge of `WE` latches an
  address and a command or data. (established; the page of this pin description is not recorded in this import)
- `RP` low aborts current and pending work, enters deep power-down and floats the data outputs (p. 4).
- `WP` low protects each block whose nonvolatile lock bit is set. `WP` high permits program and erase in every block
  regardless of those bits (pp. 4 to 5, 9).
- `VPP` must be at its 5 V programming level for program, erase and lock operations (pp. 4 to 5, 9). The datasheet's
  tolerance for that level is not recorded here.
- `RY/BY` is open drain. In its default level mode it pulls low while the write state machine is busy, and it
  releases when the device is ready, erase is suspended, or the part is in deep power-down. It stays active
  whatever `CE` and `OE` do, unless a pin-disable command changes its configuration (pp. 4, 9). That command is not
  imported here.
- `DQ0` to `DQ7` carry commands and status. `DQ8` to `DQ15` carry high array and identifier data in x16 mode and
  float during status reads (p. 4).

## Command set (p. 10)

| Write cycle | Next cycle or read | Result |
| --- | --- | --- |
| `0xff` | Read | Selects array output. |
| `0x90` | Read word address 0 or 1 | Selects identifier output. |
| `0x70` | Read | Selects compatible status output. |
| `0x50` | None | Clears CSR bits 3 to 5, GSR bit 5, and bits 5 and 2 of every BSR. |
| `0x40` or `0x10` | Write data at the destination word | Starts one word program. |
| `0x20` at any address | Write `0xd0` at an address in the target block | Starts the erase of that block. |
| `0xb0` | Write `0xd0` to resume | Suspends an erase, and resumes it. |

- A program, an erase and a suspend each select compatible status output by themselves (p. 10). (established)
- An array read follows the current read mode, even at an address read before.
- A data cycle after a setup cycle is data, even when its low byte matches another opcode. (inferred from the
  table's next-cycle column)
- The setup address of `0x20` is not used. The confirm address of `0xd0` names the block that is erased (p. 10).
  (established)
- The enhanced command set also lists page-buffer, queue, sleep, abort and device-information commands, and
  `0x71`, `0x77` and `0x97` (pp. 6, 8, 11 to 14). This unit imports the opcodes of `0x71`, `0x77` and `0x97`
  only. The contracts of the others are not imported.

## Identifier (established, p. 9)

- After `0x90`, the read at word address 0 returns `0x00b0`, and the read at word address 1 returns `0x66a8`, with
  every other address pin zero.

## Extended status (pp. 8, 11 to 14)

- `0x71` selects extended-status reads. The read address that follows, not the write address of `0x71`, selects
  a GSR or a BSR (p. 11, note 1 on p. 12). (established)
- In x16 word addresses, block `n` for `n` from 0 to 15 has its BSR at `n × 0x8000 + 1` and its GSR at
  `n × 0x8000 + 2` (Figure 6, p. 8). Word offsets 0 and 3 in each block are reserved (p. 8). (established)
- The field layouts of the GSR and BSR are in `defs/lh28f800su.toml`. The encodings are: GSR bits 5 and 4 `00`
  success or running, `01` sleep, `10` failure, `11` failure or abort. BSR bits 5 and 4 `00` success or running,
  `10` failure, `11` abort, and `01` invalid (pp. 13 to 14). (established)
- BSR bit 4 cannot assert until BSR bit 7 says ready. (inferred from the field descriptions)
- The error bits are read only after completion. (inferred from the order of the ready bit and the error bits
  on pp. 12 to 14)

## Status upload (pp. 11 to 13)

- `0x97` followed by `0xd0` uploads the status bits. Both write addresses are not used (p. 11). (established)
- At power-up every displayed BSR lock bit reads locked, even when the stored bit is clear. An upload makes each
  displayed bit reflect its stored bit (p. 12, note 2). (established)
- The stored lock bits already govern protection before an upload. (inferred)
- A `0x97` cycle with no `0xd0` after it is a setup cycle, not an upload. (inferred from the two-cycle form of
  the command)
- Page 13 lists the upload among the operations checked through GSR bit 7, but gives no upload duration. The
  duration is unknown.

## Status register (CSR, p. 12)

- Bit 7 is ready when set and busy when clear. Bit 6 is erase suspended, bit 5 is erase error, bit 4 is program
  error, and bit 3 is low `VPP` detected during an operation. Bits 2 to 0 are reserved. (established)
- Bits 5 and 4 both set after an erase attempt mean an improper command sequence. (established)

## Typical times (p. 6)

- Word program is 8 µs typical. Block erase is 0.7 s typical. The datasheet gives these as typical figures, not
  guaranteed limits. (established)
- While busy, CSR bit 7 is clear and `RY/BY` is low. (established from the status and pin descriptions)

## Reset and power (pp. 2, 4 to 7, 12)

- `RP` low aborts current and pending operations, floats the outputs, and returns all status registers to ready
  with their flags clear. The device returns to its default configuration. (p. 4) (established)
- After `RP` is released, the device returns to array mode after a 400 ns recovery interval (established). The
  supply tolerance during that interval is 5.0 V ±0.25 V on p. 4 and 5.0 V ±0.5 V on p. 7. The two differ, and
  the datasheet does not say which one applies. (unknown)
- Array data and the stored lock bits are nonvolatile (pp. 2, 5 to 6). (established)
- Whether `RP` returns the displayed BSR lock bits to locked is not stated. (unknown)
- The final contents of a word or block interrupted by `RP` or by power loss are not defined (pp. 2, 5 to 6).
  (unknown)

## Failure cases (pp. 5, 9, 12 to 14)

- The datasheet names the status fields that report low `VPP`, a locked block with `WP` low, and a program or erase
  failure. It does not state every resulting bit pattern, or any partial result, for those cases. (unknown)
- `WP` high does not change the stored lock bit. (inferred from the description of `WP` high permitting writes
  and erases regardless of the lock bits)

## Not imported

- Page-buffer writes, queued operations, sleep, abort and device-information upload. Their contracts are not in
  this unit.
- The pin-disable command for `RY/BY`.
- The `VPP` tolerance and the supply current of the programming level.
- Which board uses this part, and the wiring of its chip select, byte lanes, `WP`, `VPP` and `RP`. (unknown)
