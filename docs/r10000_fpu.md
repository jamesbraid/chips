# R10000 family floating-point denormal inputs

This page covers the R10000 family floating-point unit's rule for an arithmetic instruction with a denormalized operand while the flush-to-zero bit (FS) of the floating-point control register is clear, the Cause E bit that reports the trap, the R12000 rules with FS set, the conversion-to-long range, and what is unknown for the R16000. The constant for the Cause E bit is in [defs/r10000_fpu.toml](../defs/r10000_fpu.toml), generated to [gen/docs/r10000_fpu.md](../gen/docs/r10000_fpu.md). Nothing here was read from silicon or from a running machine.

The family covers the R10000, R12000, R14000 and R16000. The R12000 FS-set rules are recorded as facts. The rules for the R16000 are inferred from them, and are marked as such.

## Source and grades

- NEC, *VR10000 Series 64-/32-bit Microprocessor User's Manual*, fourth edition, March 2001, U10278EJ4V0UM00 (NEC UM). Printed pages 282 to 284 describe the floating-point status register (FSR, coprocessor 1 control register 31) and its exception rules. Printed page 349 is Appendix B, the R10000 and R12000 differences. The same manual is cited in [docs/o2-cpu-cache.md](o2-cpu-cache.md) with the same edition.

Every fact below marked established is stated by that manual. Cause-bit exclusivity for a single fault is inferred from the rejected operation, because the manual does not say it in those words.

## Register bits

- The Cause field is bits 17:12, listed in this order: E (unimplemented operation), V, Z, O, U and I. Established (NEC UM p. 283).
- E is bit 17. It has no enable bit and is always enabled, so an operation that sets E always takes the exception. Established (NEC UM pp. 282-284).
- Every other cause bit has an enable bit and a flag bit. Established (NEC UM p. 283).
- The flag bits are sticky and are not changed by an instruction that takes an exception. Established (NEC UM pp. 283-284).
- FS set to 0 makes a denormalized result raise Unimplemented Operation. FS set to 1 replaces the result with zero and flags nothing. Established (NEC UM p. 282).

## Denormalized inputs

- The R10000 takes Unimplemented Operation when an arithmetic instruction receives a denormalized input. The manual gives NaN inputs the same treatment. Established (NEC UM p. 349).
- The R12000 with FS clear behaves as the R10000. Established (NEC UM p. 349).
- The manual applies the input rule to arithmetic instructions in general and names add, subtract, multiply-add, convert, divide, square root, reciprocal and reciprocal square root. Established (NEC UM p. 349). This page's rule covers only ADD.S and DIV.S arithmetic with FS clear. The rest of the list is unknown for this rule until each operation is checked.
- A rejected instruction does not store its result, and its flag bits do not change. Established (NEC UM p. 284).
- A denormalized result with FS clear takes the same Unimplemented Operation path as a denormalized input. Established (NEC UM p. 282).
- MOV and conditional MOV take no exception for denormal or NaN inputs, with either FS value. Established (NEC UM p. 349). This conflicts with the wording on p. 283, which says these instructions can set the Unimplemented Operation exception in the Cause field. See the unknowns below.
- The R12000 with FS set replaces a denormal input with zero before the operation, and the operation then behaves as it would with a zero input. The Inexact bit is set unless the other operand fixes the result. Established (NEC UM p. 349).

## R12000 with FS set, other operations

The manual also describes these R12000 rules with FS set. They are recorded here as facts. Nothing here was checked on a part. The page numbers were carried from an earlier reading of the manual and have not been re-checked against it.

- ABS, NEG and compare flush a denormal input. Established (NEC UM p. 349).
- Floating-point to integer conversion flushes a denormal input and sets Inexact. Established (NEC UM p. 349).
- A quiet NaN input produces the standard quiet NaN, whatever its payload. Established (NEC UM p. 349).
- A denormal produced by an operation is handled as on the R10000, whatever FS says. Established (NEC UM p. 349).
- MOV and conditional MOV never trap. Established (NEC UM p. 349).

## Conversion to long (CVT.L)

- The R10000 takes Unimplemented Operation when CVT.L cannot represent its result in 51 bits. Its manual's CVT.L text says "only up to 51 bits". The corrected wording (from 52) is in the manual's v1.1 errata. Established for the R10000 text (MIPS R10000 User's Manual, v2.0, p. 312, with the errata correction on p. 288). This page does not check the errata text itself.
- Whether "51 bits" means magnitude below 2^51, and where the negative boundary falls, is not stated. Unknown.
- The R12000 manual keeps the trap for unrepresentable conversions but gives no bit count. Established (NEC UM p. 350). The R12000 bound is unknown.
- The R14000 and R16000 bounds are unknown.

## R16000 (inferred)

- The R12000 FS-set rules above are assumed to hold on the R16000. Inferred. No cited source describes the R16000 FPU.
- The R16000 trap boundary for CVT.L is unknown; see the unknowns below.

## Inferred

- When a single denormal input traps, E is the only cause bit set. Inferred from the manual's description of the rejected operation, not stated outright.

## Unknown, and what would settle it

- **FS bit position.** The bit positions in the FCSR figure on p. 282 were not read as text for this import. Settled by reading the figure, or by a register readback.
- **ABS, NEG and compare with FS clear.** The manual describes flushing these with FS set (p. 349) but does not say whether the R10000 traps on a denormal input to them. Settled by the manual's R10000 text or by a trap test on the part.
- **Conversion operations and square root with FS clear.** The manual's list names them, but this rule was not checked for each one. Settled by a test per operation.
- **MOV wording conflict.** Settled by a test on a real R10000 or R12000 that runs MOV with a denormal input, with FS clear, and reads the FCSR afterward.
- **Cause-bit exclusivity.** Whether any other cause bit is set on the trap. Settled by reading FCSR at the exception handler on a real part.
- **Physical capture.** No FCSR capture for this rule exists in this repository. The manual states the family rule. A capture from an R10000 or R12000 would show what the part does under a single denormal input with FS clear.
- **Revision-specific behavior.** Errata and any difference between steppings were not checked.
- **R16000 denormal inputs with FS set.** Whether the R16000 flushes a denormal input in hardware or traps to software. Both give the same architectural result, so software cannot tell them apart. Settled by a timing or trap-count test on an R16000 part, comparing a denormal-input loop with FS set against the same loop with normal operands.
- **CVT.L bound on the R12000 and later.** The number of bits that CVT.L can convert without a trap, and the exact boundary values. Settled by a trap test on the part, with FS clear, over values either side of the R10000 limit.
