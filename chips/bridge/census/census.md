### Scan coverage and what is unresolved

- Accessor functions seeded (`seeds.args`): ip27-unix 105, 105 with at least one resolved access; ip30-unix 105, 105 with at least one resolved access; ip35-pcibr 105, 105 with at least one resolved access.
- Window pointers passed to a callee the config does not seed (**unresolved**, site in `work/bridge/unresolved.tsv`): 9 distinct sites.
  - ip27-unix `xbridge_attach` @0708dc calls `xtalk_intr_connect` with the window pointer in a4
  - ip30-unix `xbridge_attach` @042624 calls `xtalk_intr_connect` with the window pointer in a4
  - ip35-xbridge `xbridge_attach` @128 calls `pcireg_nic_addr` with the window pointer in a0
  - ip35-xbridge `xbridge_attach` @134 calls `pcireg_nic_addr` with the window pointer in a0
  - ip35-xbridge `xbridge_attach` @158 calls `pcireg_nic_addr` with the window pointer in a0
  - ip35-xbridge `xbridge_attach` @1d0 calls `pcireg_id_get` with the window pointer in a0
- Loads and stores in the seeded scope whose base register the scan could not resolve and whose displacement falls where registers live (0x100..0x2ff): 225, almost all `xbridge_attach` writing its own state record (**unresolved, inspected only by listing; `suspects.tsv`**).
- Index registers are not followed: a family reached through an array index is recorded at its base with `idx=1` (device 0..7, interrupt 0..7, ATE). The family extent comes from the datasheet, not the code.
- Returned pointers: a function that hands back a pointer into the window is recorded as a kind-`a` site at the pointer offset (this is how the one-wire register and the configuration windows are reached).
- Basic blocks never reached by the flow analysis (jump tables) in the seeded scope: ip27-unix 30, ip30-unix 29, ip30-prom 0, ip35-pcibr 30, ip35-xbridge 9, ip35-prom 0, io6-prom 0.
